# PRD Quality Review — Product Requirements Document (PRD) — Meme & Reaction Image Organizer (Draft v2.0, revised 2026-09-27)

## Overall verdict

**Adequate.** v2.0 closes all three prior criticals on the page: the environment question is now a decision with dated evidence (NFR-A5, §2.4:72), classification is load-bearing through AC-A6/AC-A7/AC-A11 (§2.5:81-82, 86), and the flagship degraded demo is specified (FR-A6, §2.3:61 + AC-A9:84) — the doc is no longer satisfiable end-to-end with zero ML working. What's at risk is the gap between that declared environment and the repo it governs: NFR-A5's setup exists only in the PRD (`requirements.txt:4` still pins `tensorflow>=2.15,<2.20`, no `pyproject.toml`/`.python-version` exist), the shipped label→category mapping has no authoring or coverage requirement, and the companion `system-architecture.md` still carries pre-v2.0 AC IDs and the old corrupt-image hedge. Done-ness, scope honesty, downstream usability, and shape fit remain adequate-but-bending; decision-readiness, substance, and strategic coherence are now genuinely strong.

## Done-ness clarity — adequate

All nine FRs now carry at least one testable AC (FR-A1→AC-A1/A4, FR-A2→AC-A6/A9/A11, FR-A4→AC-A2, FR-A5→AC-A3, FR-A6→AC-A1/A9, FR-A7→AC-A4/A6, FR-A8→AC-A8, FR-A9→AC-A11), the threshold has a value and a range, NFR-A3 is bounded ("byte-identical", "zero writes outside the output root", §2.4:70), and NFR-A1/NFR-A5 are exercised by AC-A5's exact command (§2.5:80). This is a real upgrade over v1.0. It stops short of strong in three places: the product's central artifact (the mapping) has no authoring requirement, the threshold's override path has no AC, and the CNN training FR has no quality bar — plus two vocabulary gaps a test author must guess.

### Findings
- **medium** The shipped label→category mapping has no authoring, sizing, or documentation requirement (§1:18-21; FR-A2:55-57; Glossary §2.7:102) — FR-A2 and the glossary say a "shipped mapping" exists, but no FR requires it to be *authored, sized, or justified*, and the only constraint is AC-A7's aggregate ≤80% `unsorted` bound. The table that does exist has 13 entries (`classifier.py:55-73`) including exactly the Q&A-magnet assignments H1 flagged (`monitor → chaotic-screenshots`, `seashore → wholesome-posts`); nothing in the PRD would fail those. An engineer cannot state "done" for mapping content, and the defense question "how did you justify this mapping?" has no document to point at. *Fix:* extend FR-A2: mapping lives in a documented artifact with ≥N entries per category and a one-line rationale per entry; add an AC on mapping coverage per category (not just aggregate `unsorted` share).
- **medium** FR-A3's override path and out-of-range behavior have no AC and no stated consequence (§2.3:58 vs §2.5) — default 0.45 and range `(0,1]` are now stated (fixing v1.0), but no AC exercises `--threshold` or asserts that a below-threshold image lands in `unsorted` with a reason, and the behavior of an out-of-range value (`--threshold 0`, `--threshold 1.5`) is unspecified despite the declared range. *Fix:* one AC: "image scoring below threshold → `unsorted`, reason logged; `--threshold 0.9` changes the outcome; out-of-range value rejected with exit 1."
- **medium** Trained-artifact quality is unbounded (FR-A9 §2.3:64; AC-A11 §2.5:86) — AC-A11 requires only that the artifact be *loadable* and that inference *returns* category + confidence; a model that trains for one epoch and outputs uniform guesses passes, and no train-time contract (split, seed, epochs, minimum dataset actually verified) is stated beyond the ~10-images assumption. This is C2's shape reproduced at the CNN layer. *Fix:* either bound it ("training completes on ≥10 images/category; artifact achieves ≥X on a held-out split") or explicitly state "train runs; quality not gated" with a `[NOTE FOR PM]` and let OQ-2 carry it.
- **low** FR-A7's report vocabulary and accuracy formula are undefined (FR-A7 §2.3:62; AC-A6 §2.5:81 vs Glossary §2.7:93-102) — "refused vs failed" and "placement accuracy" appear nowhere in the glossary, and it is ambiguous whether AC-A6's "5 categories, 2 each" counts `unsorted` as an expected category (i.e. whether 2 fixture images are *supposed* to land in `unsorted`). *Fix:* glossary entries for refused/failed and placement accuracy (one formula: correct-category matches ÷ fixture size, `unsorted` = wrong); state whether `unsorted` is one of the fixture's five.
- **low** Partial-failure exit semantics unspecified (FR-A8 §2.3:63) — 0 covers "success (reported skips included)", 1 covers "runtime/filesystem error (e.g. missing input dir)", but a run where some individual moves raise `OSError` mid-batch is neither: continue-and-report-as-0 or abort-as-1 is unstated, while FR-A7 now counts such errors. *Fix:* one clause — "per-file failures are reported and do not change the exit code; ≥1 filesystem failure → exit 1" (pick either rule, state it).
