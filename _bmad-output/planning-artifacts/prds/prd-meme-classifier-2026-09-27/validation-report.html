Adversarial review

Verdict: REJECT — major revision required. The PRD is currently satisfiable end-to-end with zero machine learning working, contains at least one self-contradiction between acceptance criteria and implementation/architecture, mandates an FR whose dependency stack cannot be installable under the project's own pinned requirements, and specifies no correctness measure for the classifier it exists to deliver. Each of these is a defense Q&A kill-shot. Environment facts verified 2026-09-27: tensorflow>=2.15,<2.20 → No matching distribution on Python 3.14.6; only 2.22.0rc0 exists for cp314; both backends are stubs; 17 tests cover organizer only.

critical

C1 — FR-A2 unconditional, but dependency stack not installable as pinned; no contingency

§2.3 FR-A2 · §2.4 NFR-A1 · §4
FR-A2 requires both backends as functional requirements with no qualifier, yet requirements.txt pins TF <2.20 — verified uninstallable on the committed Python 3.14.6. No fallback backend, no version constraint, no environment requirement, no acceptance path for "backend unavailable": FR-A8's exit code 2 has zero ACs, so a run that exits 2 and does nothing is "compliant". Downstream: the Dev epic for FR-A2 cannot be started until someone picks (a) install the RC, (b) downgrade Python, or (c) change backend — a decision the PRD owns and hasn't made. Defense: "Can you run your classifier right now?" → No. "Your requirements file installs?" → Verified: no.
Fix: Resolve the environment/backend decision first — pin a runnable path (Python downgrade → TF 2.19/2.20, explicit RC acceptance, or a non-TF backend) and rewrite FR-A2 accordingly. Nothing else in the Dev phase is estimable until this exists.
critical

C2 — No acceptance criterion requires the classifier to classify; all 5 ACs pass with NotImplementedError stubs

§2.3 FR-A2, FR-A3 · §2.5 AC 1–5
AC-1..AC-5 verify dry-run counts, folder allow-listing, collisions, non-image skips, and pytest green. Not one asserts "this cat image ends in cat-memes/". No accuracy/precision/recall requirement anywhere — ironic given the sibling deliverable mandates accuracy_score, classification_report, confusion_matrix. A file-mover with a hardcoded unsorted label satisfies this PRD. QA gets no oracle; epics will encode "tests pass" instead of "classification correct".
Fix: Add classification ACs with a measurable oracle — a small labeled fixture set (even 10 hand-picked images) with expected categories and a minimum pass rate; report per-category results like the sibling project.
critical

C3 — AC-1 (flagship demo) depends on a loadable backend; dry-run-unavailable behavior unspecified

§2.3 FR-A6 · §2.5 AC-1 · §2.4 NFR-A1
Planned moves require a category, which requires classification; cli.run() loads the backend before organizing, so in the committed environment py main.py data/inbox --dry-run exits 2 with no report. AC-1 is unpassable as written on the machine the project runs on. The PRD nowhere says dry-run must work without TensorFlow, nor how a destination is planned when the backend is down.
Fix: Specify dry-run-without-backend semantics in one sentence (report-as-unsorted? placeholder? bail?), then make code, architecture, and AC-1 agree.
